# TASK-007: generic production task engine (drop the A/B test mindset)

Closes #52 (scope reframed 2026-11-14: the A/B versions and the cheetah
poster were probes, not the goal). The goal is a frozen core with zero
manual code edits per task: any legal MiniMax-H3 video task starts from
a declarative JSON spec, target >=95% single-start end-to-end success.

## Task 1 — generic `--task-spec` (the centerpiece)

- New `h3_task_spec.py`: fail-closed `TaskSpec` / `RefImage` schema
  (`task_id` / `output_prefix`, `ref_image_1` node 137 required,
  `ref_image_2` node 139 optional defaulting to ref 1, `prompt` XOR
  `shots[]` deterministic rendering, `seed` required, `width`/`height`
  16-multiples, `animation_frames % 17 == 5`, `tail_card_frames` default
  0, explicit `output_width`/`output_height` default 1080x1920).
- `h3_contract.patch_api_workflow_for_spec()` parameterises the patch;
  the old `patch_api_workflow()` delegates to it (proven byte-identical
  for A and B on the fixture graph and the real `workflow_api.json`).
- `run` / `preflight` / `plan` / `archive` accept `--task-spec`; with
  it, `--variant` is no longer required. `--variant A|B` survives only
  as a built-in fixture adapter. `run` still requires
  `--production-task-id`, which must equal the spec's `task_id`.
- Worker verifies both received ref images against the spec SHA-256
  before inference; `assemble.py` / `h3_video_qa.py` /
  `h3_output_check.py` are parameterised (tail 0 = no tail assembly;
  the tail stream is now scaled/cropped to the output size — the old
  filter only worked because the A/B poster happened to be 1080x1920).
- `config/task_spec.example.json` is the A fixture as a plain spec
  file, generated from the adapter and locked by a test.
- `scripts/run_h3_ab.sh` accepts `--task-spec` XOR `--variant`;
  `docs/runbooks/generic-task-spec.md` is the new standard entry,
  `docs/runbooks/production-run.md` updated to it.

## Task 2 — concurrent 40 GB restore

- `DEFAULT_CHUNK_SIZE` 1 MiB -> 8 MiB; fresh files >= 256 MiB download
  in 4 sharded Range requests with merge-into-`.part`, 200-response and
  shard-exhaustion fallback to single-stream, 403 fail-closed, token
  refresh inside the thread-safe provider, progress-error fatal (no
  fallback). Final size + full SHA-256 + post-metadata + atomic
  `os.replace` unchanged.
- `_download_progress()` milestone fix: monotonic `done >=
  next_milestone` instead of the exact-divisibility assumption.

## Task 3 — preflight gates at 0 CU

- Dual-token mint proven in preflight (`drive.readonly` metadata read
  over the `requests` + `certifi` transport, `drive.file` zero-write
  archive probe); `invalid_scope` surfaces before any GPU.
- `--task-spec` is validated inside preflight (schema, ref existence /
  SHA-256, workflow patch), covered by an end-to-end preflight test
  with all live boundaries stubbed.

## Task 4 — shutdown executor hardening

- `--production-task-id` (mandatory for `stop --confirm-stop`,
  filter for `audit`); out-of-task leases skipped as
  `out_of_task_scope`.
- `emergency_deadline_utc` (`started_at + max_wall_sec + 900s`) caps
  unfinalised leases; past it, `query_session_state` triages
  STOPPED / ACTIVE / UNKNOWN. `_update_gpu_lease_deadline` local
  write is fail-closed.
- Runbook updated.

## Tests

- Local: `run_ci_tests.py` 642 tests, 0 failures, 0 errors
  (2 poster-gated skipped); full `unittest discover` 644 tests with
  exactly the 2 by-design poster errors in a clean checkout.
- New: `tests/test_task_spec.py` (36), concurrent-download tests +
  constants (9), `_download_progress` milestone test (1).
- Also fixed a latent harness type lie the new preflight test exposed:
  the chain harnesses mocked `ledger_path_for_task` to return a `str`
  (real signature is `-> Path`); the leaked module-global
  `LEDGER_PATH` broke any later real `preflight()` in the same
  process. Both harnesses now return a `Path`.

## Not in this PR

- No GPU, no CU, no cron deployment. Production-dir sync, prod CLI
  install, prod manifest generation and the zero-GPU live acceptance
  run separately after merge (same procedure as TASK-005/006).
- `environment_manifest.json` is NOT replaced by a prod-generated
  copy: the gated fields (CLI 0.7.5, patched client hash, both patch
  booleans, ffmpeg/ffprobe) are identical between venvs, and the prod
  `workflow_api.json` hash may differ from the repo canonical file.
- No constants changed; no workflow change; no story/prompt/image/
  resolution/steps change.
