# AGENTS.md — colab-workstation

How to work in this repo. Read this before changing anything.

## The rules that matter most

1. **Never spend CU or create a GPU from a routine task.** Live runs need
   the user's explicit go-ahead for THAT task and `--confirm-live`.
   (A TTY is only needed for the legacy interactive mount path; the
   default download path is noninteractive — TASK-006 P0-B.)
   CI never touches a GPU, Drive, or any credential.
2. **Per-task 30 CU, never cumulative** (ADR-001). If someone says "add
   30 CU", treat it as a NEW task with its own ledger — never top up an
   old one. The controller refuses `--project-budget-cu` ≠ 30.0.
3. **Fail closed, don't paper over.** A bare exec returncode 0 is not
   success; a mount exit 0 is not proof of a mount; a READY flag file is
   not proof of a depot. If a check fails, say so with the evidence.
4. **Flat root is deliberate** (ADR-003). Production `.py` files stay
   flat at the repo root so imports keep working. No package refactor in
   a drive-by commit; no stub modules under `workstation/`.
5. **No credentials in git, ever.** No tokens, refresh tokens, cookies,
   passwords, proxy auth, ADC files, ledgers, or session state. Drive
   file IDs and hashes are fine (non-credential references). Run the
   secret scan before every commit.
6. **No third-party runtime.** No `colab-dfs-ext`, no Mac GPU relay, no
   Antigravity runtime, no model substitution without a pinned revision
   and its own PR (ADRs 004–005).
7. **Don't upgrade audit claims into facts.** Third-party audit
   judgments stay PROPOSED_ONLY until Muse verifies them with its own
   runs and tests. Record the run id or it didn't happen.

## Everyday commands

```bash
# Offline (safe anywhere)
python -m py_compile *.py
python tests/run_ci_tests.py            # full suite minus 2 poster-gated tests
python -m unittest discover -s tests -q # 224 tests; 2 poster errors expected in clean checkout
python scripts/check_workflow_schema.py
python scripts/verify_patch.py
python scripts/verify_manifest.py      # after any file change, regenerate the manifest first (below)
python scripts/check_docs_index.py

# Read-only live checks (colab usage/sessions only)
./scripts/preflight.sh
./scripts/check_sessions.sh
./scripts/check_budget.sh
./scripts/verify_drive.sh
./scripts/verify_shutdown.sh

# Live GPU run (spends CU; operator + TTY + explicit confirmation only)
# --production-task-id is required: a new task id never gets a fresh
# 30 CU silently; add --authorize-new-task only with user approval.
./scripts/run_h3_ab.sh --confirm-live --production-task-id h3-ab-20261112 --variant A --run-id h3-<UTC>-<suffix>
```

## Making changes

- Flow: Issue → feature branch → tests → pull request → review → merge.
  Never commit directly to `main`.
- After changing any tracked file, regenerate `SOURCE_MANIFEST.json`
  (see `scripts/verify_manifest.py` — the manifest is generated by a
  script over the tree; never hand-edit hashes) and re-run
  `scripts/check_docs_index.py` + the secret scan.
- If you change a constant in `h3_contract.py` / `h3_budget.py`, update
  `config/*.yaml` and `jobs/minimax_h3_ab/job.yaml` in the same PR —
  `tests/test_config_contract.py` will fail otherwise.
- If you change the workflow, update `workflow_api.json` AND
  `workflows/api/workflow_api.json` (byte-identical copies) AND the
  schema if a pinned node changed. `scripts/check_workflow_schema.py`
  enforces the copy + the patch contract.
- New CLI patches go in `patches/google-colab-cli-0.7.5/` as real diffs
  against the pristine wheel, with a preflight gate and a docs entry.
  Documented behaviour is not an auto-applied diff — label it honestly.
- Incident records: one file per incident in `docs/incidents/`, with
  STATUS + EVIDENCE (run_id, file/function, test). Never mark
  CONFIRMED_FIXED without a real run id.
- The two poster tests fail in a clean checkout by design. Do not
  "fix" them by committing the poster, and do not delete them. If the
  poster policy ever changes, that is a separate decision with its own
  record.
